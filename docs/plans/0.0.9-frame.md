## Stage 2: build in stages, lightest first

Keeps memory and disk in check: never build gpui-kit, CubeCL's CPU backend (LLVM) and wgpu at
once.

**Setup, once.**
- Linux: install the GPUI system libraries:
  ```sh
  sudo apt-get install -y build-essential clang cmake pkg-config libssl-dev \
    libxkbcommon-dev libxkbcommon-x11-dev libx11-xcb-dev libxcb1-dev \
    libfontconfig-dev libwayland-dev libvulkan-dev libasound2-dev libzstd-dev
  ```
- macOS: Xcode command-line tools are enough (Metal).
- `export CARGO_BUILD_JOBS=2` if memory is short (raise it on the dev machine).

**Each stage:** `cargo check` → `cargo test` → note disk and memory → commit fixes, push.
`scripts/check-all.sh` runs them in order (`CHECK_ONLY=1` for checks alone, `CLEAN=1` to free
disk between stages).

| Stage | Crates | Commands |
|---|---|---|
| A | kitchen-artifacts, kitchen-plugin, kitchen-tool, kitchen-net, kitchen-hub | `cargo check -p kitchen-artifacts -p kitchen-plugin -p kitchen-tool -p kitchen-net -p kitchen-hub` then `cargo test` with the same `-p` list |
| B | kitchen-ui, kitchen-views, kitchen-shell, kitchen-code, kitchen-agent | same, with these crates; then `cargo test -p kitchen-views --features h264`; then run the galleries: `cargo run -p kitchen-ui --example gallery`, `cargo run -p kitchen-shell --example gallery`, `cargo run -p kitchen-code --example code_gallery` |
| C | kitchen-compute without and with the CPU runtime | `cargo test -p kitchen-compute`, then `cargo test -p kitchen-compute --features cpu` |
| D | kitchen-compute on the GPU | `--features wgpu`, and `--features cuda` where there is CUDA |

- [ ] A green, pushed
- [ ] B green, pushed (galleries open and look right)
- [ ] C green, pushed
- [ ] D green, pushed
- [ ] `cargo clippy --workspace --all-targets` and `cargo fmt --check` clean
- [ ] `cargo deny check` (supply-chain workflow) passes with the new dependencies:
      lsp-types, similar, image, mp4, openh264, smallvec, anyhow

Where to look first if a stage fails:
