# 0002. History is append-only, and a change carries the whole body

**Context.** Many interfaces, people and agents will write the same records, often at the same
time, often generated by tools that never saw each other. Overwriting state loses edits silently
and leaves no audit. Patches need a shared patch format and break when one is lost.

**Decision.** Records change only by appending changes. Each change carries the record's whole
body after it, names the changes it follows (`prev`), and is named by its content ID. Concurrent
changes produce two heads, visible to every reader, resolved by a later change.

**Consequences.** Nothing is lost; audits and "what did the agent do?" are a read; any interface
can rebuild any view. Storage grows with every change (bodies are small; blobs are not repeated);
compaction is an open question. Apps must handle a record in conflict, which most never see.

**Alternatives.** Last-writer-wins state: simpler, loses data. CRDTs merging bodies automatically
(Automerge-style): powerful for text and collaborative documents, but they fix merge semantics
in the protocol, and ledgers and lab records want a person or an app to decide. A store may still
use CRDTs inside a schema's body; the protocol stays neutral.
